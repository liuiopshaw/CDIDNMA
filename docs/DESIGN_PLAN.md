## 一、项目目标与边界

构建面向 CDI 抗菌电极的多 agent 系统。系统在给定场景下，自主完成跨家族候选生成、评估排序、性能预测和机理探究。研究同时关注材料价值与方法价值，当前优先证明多 agent 方法的作用。

系统输出三类结果：

1. **量化评价与可调整排名**。逐维度评分，附证据和不确定性。权重与研究约束可调整，所有版本留档。
2. **条件化性能预测**。尽可能给出 ROS 和抗菌性能的合理区间，说明文献锚点、工况差异和外推依据。
3. **可证伪的机理假设**。给出主要 ROS 路径、可能贡献、竞争解释和反向证据，说明何种结果会否定判断。

真正灭活和出水细菌去除均为优先目标。二者分别定义、存储和评估。ROS 任务的优先顺序为：**浓度、生成量或速率的量化 → 对灭活的贡献 → 候选间 ROS 能力排序**。

### 1.1 自主运行与独立调用

完整流程由编排程序执行。agent 通过共享工作区协作，正常运行不要求人工审批或逐项补充实验信息。

每个子 agent 都提供独立调用入口。使用者可以输入研究目标、指定材料或已有记录，单独执行生成、评估、性能预测或机理分析。独立调用与完整流程使用相同的数据契约和结果格式。

自主完成包括生成有证据的结果，也包括主动保留未知项。系统通过检索、带假设判断或明确弃答处理缺失信息，并在预算内结束本轮任务。

### 1.2 当前研究案例

先导材料已经完成制备和实验。用户固定使用该材料进行当前案例验证，同时保留跨家族比较。其他候选可以排名更高，榜单不要求先导材料始终第一。

当前研究采用已有实验数据开展回顾性评估。系统可以支持未来研究者录入新实验，但本项目的近期验收不要求更换材料或重新完成一套实验。

### 1.3 系统边界

- 材料判断由 LLM 完成。工具提供事实；代码负责算术、单位换算、格式校验和流程控制。
- 合成信息只到文献已有方法、原料类别和可行性的层级，不输出具体操作步骤。
- 不包含实验设计、实验执行和论文撰写功能。
- 不微调通用大模型，不引入统计机器学习做性能回归，不使用对抗式 agent 辩论。
- 允许后期微调本地小模型，专用于文献提取等单一任务。微调不是 MVP 前提。

## 二、先导材料与已知场景

以下信息由用户在本轮讨论中提供。用户已确认存在完整实验数据；具体数据文件尚未在本轮导入或核验。

| 项目 | 已知信息 |
|---|---|
| 活性单元 | 铜纳米团簇 |
| 配体 | 4-巯基苯甲醛，用户简称 MBA；保留全名，不按缩写自动替换为其他化合物 |
| 包覆或限域结构 | 原始 ZIF-67，区别于 ZIF-67 衍生材料 |
| 导电载体 | 炭黑 |
| 目标电极 | 上述复合材料作为阳极 |
| 阴极 | 活性炭 |
| 水体系 | 含菌纯水相 |
| 外加电压 | 1.2 V；电压定义和参比信息尚未明确，不能直接视为阳极电势 |
| 流动方式 | 单次流过，1 mL/min |
| 时间与采样 | 装置运行 0–60 min，每隔 5 min 取出水样 |
| 目标菌及初始浓度 | 大肠杆菌，10⁶ CFU/mL |
| 外部条件 | 无光照、无曝气、无外加氧化剂 |
| 菌数数据 | 来自出水计数，不包含电极上截留细菌的存活情况 |
| 已有 ROS 数据 | H₂O₂ 和 ·OH，有标定的浓度、生成量及清除剂实验；有对照 |
| 其他已有数据 | 材料表征和杀菌性能测试，具体字段以导入记录为准 |
| 缺失水质参数 | pH、电导率、溶解氧均无记录，保留为未知 |

运行时间与水力停留时间分别存储。0–60 min 是装置运行及采样时间，不能作为单次水样的接触时间。无曝气只表示没有额外供气，不等于无溶解氧。

现有出水数据可直接验证出水 CFU 降低及对应的 log 去除。它不能单独确定整个体系的真实灭活程度。真实灭活保留为研究目标，依据其他证据形成单独判断。

上述场景是当前案例的输入档案，不是所有使用者必须采用的条件。未知参数不阻塞全部流程，也不要求用户近期补测。

## 三、候选空间与排名原则

### 3.1 跨家族候选空间

候选限定在纳米材料电极范围，覆盖纳米颗粒、纳米团簇和单原子三类活性单元。材料身份拆分为：

```
候选 = 活性单元类型与组成
     + 配体
     + 包覆或限域框架
     + 导电载体
     + 结构与负载信息
```

MBA 配体、ZIF-67 框架和炭黑载体分别记录。金属组成、粒径、负载量等未知信息保留为空，不以名称补全实测结构。

候选生成可采用代码枚举组合、LLM 判断可行性的方式；具体方案待候选生成专题定稿。只有枚举项和离散化规则明确时，才能报告搜索空间总量及覆盖率。枚举出来的组合不自动等于可行材料。

先导材料作为使用者指定的候选进入比较，记录其来源。不能将指定候选描述为系统自行发现。

### 3.2 默认评分与灵活排名

沿用当前五维默认权重，作为后续评估的起点：

| 维度 | 默认权重 | 评价内容 |
|---|---|---|
| ROS 生成潜力 | 30% | 目标电极位置和条件下的 ROS 证据 |
| 结构与稳定性 | 20% | 框架保持、循环表现及金属溶出风险 |
| CDI 适配性 | 20% | 导电性、孔结构、润湿性与目标运行场景 |
| 合成可行性 | 15% | 通用实验室条件下的文献方法可行性 |
| 新颖性 | 15% | 在声明的检索范围内与已有体系的差异 |

分档见 [rubric.md](rubric.md)，当前数值配置见 [config/rubric.yaml](../config/rubric.yaml)。本次仅修订设计文档，配置文件尚未实现新的场景、权限和预算设置。

维度分数、证据与不确定性单独保存。仅调整权重时，由代码重算总分和排名；调整判据、场景或证据时，重新评估受影响的维度。每次运行保存候选范围、评分规则和权重快照。

用户可以查看先导材料在不同偏好下的排名。研究偏好公开记录，排名变化附原因，不通过修改证据或无依据提高分数保证首位。

正式方法比较提前固定规则。看到评估结果后调整的版本归入探索性分析，不能继续当作原有留出测试。综合总分表示研究优先级，不直接等于杀菌效力或实际 ROS 浓度。

## 四、数据层与证据要求

### 4.1 三层文献库

| 层 | 用途 | 当前记录数 |
|---|---|---|
| `cdi_core` | CDI 抗菌与电极材料的核心证据 | 262 |
| `electrocatalysis_prior` | 电化学消毒、氧还原、电芬顿等机理先验 | 905 |
| `photocatalysis_inspiration` | 材料设计灵感 | 333 |

2026-10-10 核查确认，合并文件包含 1500 条记录和 1500 个规范化后不同的 DOI。目前主要是标题与 DOI，尚不等于 1500 条可用的定量证据。

核心层标题初筛使用 `disinfect|antibacter|antimicrob|bacteri|inactivat|steriliz`，共命中 18 条。其中包含消毒副产物前体等非直接杀菌研究。标题筛选也可能漏检，实际相关数量须经摘要或全文分类确认。旧版“约 80 篇 CDI 杀菌文献”的估计不再作为设计依据。

数据审计分别统计相关性、全文可得性、可用工况、定量抗菌结果和直接 ROS 证据。50 篇可作为初期处理规模参考，不要求凑足 50 篇可比较的 CDI 杀菌研究。

### 4.2 可迁移性按结论判断

检索优先级保持 CDI 核心、电催化先验、光催化灵感。CDI 抗菌与普通 CDI 电极记录使用子标签区分。光催化层不参与当前无光场景的性能数值锚定。

每条证据记录电极位置、材料形态、关键工况和适用结论。双电子氧还原等阴极证据不能直接记成先导阳极材料自身的 ROS 能力。阴极生成物参与全装置反应可以作为待核验路径，须说明生成位置与作用位置。

同一文献中的多个样品和工况分别存储，同时保留共同来源。不能把这些记录当作相互独立的研究，也不能混入同一样品的数据。

### 4.3 可追溯证据

证据至少包含：来源 ID、DOI、材料或样品 ID、原文位置、原始数值与单位、工况、提取方式，以及支持或反对的具体结论。

明确区分原文测量结果、原作者解释和系统推断。来源存在不等于支持结论。表格、图和正文数据都需要定位，结论与证据之间保留对应关系。

未知、未报告、低于检测限、模型冲突和真实零值分别记录。置信度标记说明判断依据，不能默认解释为经过校准的正确概率。

### 4.4 全文访问与处理边界

自动采集以已明确允许访问和处理的来源为基础。OA 状态、全文链接、处理范围和远程发送限制分别记录。

OA 覆盖率尚未统计，机构 TDM 范围尚未确认。权限不明确或全文不可得的记录标记为受限，系统继续处理其他可用资料。机构许可不是其他设计任务的前置条件。

仅允许本地处理的内容使用本地路径。若冲突需要远程仲裁而不允许发送，该字段保留未解决状态；不因仲裁流程而自动外发全文。本地部署也不能替代访问和使用范围的确认。

## 五、共享工作区与数据契约

采用黑板模式。所有 agent 从共享工作区读取已发布记录，仅追加自己负责的结果。历史结果、来源和版本保持可追溯。

以下为数据结构的设计范围，具体字段与约束留待 P0 专题定稿：

| 记录 | 主要内容 |
|---|---|
| 文献来源 | 元数据、全文位置、层级、处理范围 |
| 材料实体 | 活性单元、组成、配体、框架、载体、同义词、来源 |
| 场景 | 电极角色、水体系、电压定义、流动方式、时间定义、菌种及缺失字段 |
| 证据条目 | 样品、原文定位、测量对象、数值、单位、工况、提取与质检状态 |
| 基元与综述卡 | 可复用结构关系、适用条件、支持与反向证据 |
| 候选 | 材料组合、设计依据、指定或生成的来源、场景关联 |
| 评估与排名 | 逐次分数、聚合结果、权重版本、裁决与理由 |
| 性能预测 | 目标量、单位、时间含义、区间或趋势、锚点、假设、未知项 |
| 机理假设 | 反应位置、路径、贡献判断、替代解释、证伪条件 |
| 知识缺口 | 缺失项、受影响结果、检索历史、预算、解决状态 |
| 运行记录 | 输入快照、模型与提示词版本、调用关系、成本、错误和完成状态 |
| 验证对比 | 实验来源、结果留出范围、预测版本、比较结果与无法判断项 |

工作区分暂存区与正式区。提取结果经自动检查后晋升，冲突和无法定位的字段继续保留质量标记。归纳使用正式区记录，并继承原始证据限制。

流程状态、筛选裁决和验证结论分别保存。任务可以完成并包含未知项；候选可以因证据不足 hold；验证对比可以完成但结论不支持预测。不能把导入实验数据或完成对比自动等同于“预测得到证实”。

## 六、Agent 分工与两种运行模式

### 6.1 六类子 agent

| 子 agent | 职责 | 独立调用用途 |
|---|---|---|
| 文献提取 | 提取材料、条件、性能与证据位置，写暂存区 | 处理新增文献或指定字段 |
| 知识归纳 | 整理活性基元、结构关系和适用条件 | 更新某个材料家族的知识 |
| 材料预测 | 生成跨家族候选、结构组合和设计依据 | 按目标生成候选，或登记指定材料 |
| 评估筛选 | 评分、比较、排序并识别缺口 | 评估指定材料或重算榜单 |
| 性能预测 | 文献锚定、工况对齐、量化区间和趋势判断 | 预测指定材料的 ROS 与抗菌指标 |
| 机理探究 | 分析 ROS 路径、可能贡献、替代解释及证伪条件 | 从结构推断机理，或解释已有结果 |

材料预测负责候选设计；性能预测负责数值估计。筛选中的机理可行性是初步条件检查；机理探究负责详细路径，避免重复输出同一结论。

### 6.2 完整流程

```
研究目标与场景
  → 文献检索、提取、自动检查、知识归纳
  → 跨家族候选生成
  → 评估筛选
  → 性能预测
  → 机理探究
  → 候选档案与运行报告
```

编排程序按固定主流程调度，缺口触发有预算的补充检索和重评。上游任务既可由新文献事件触发，也可由编排程序按需触发，不需要人工先完成入库。

完整流程优先深入分析通过筛选的候选。用户指定的先导案例可单独进入预测与机理分析，同时保留其原有评分、裁决和质量标记。

### 6.3 独立调用

独立任务接收研究目标、材料或记录引用、可用场景、允许使用的证据及预算。agent 自动读取依赖、复用缓存，并在必要时发起补充检索。

独立运行不要求完成整个前置管线。信息仍不足时，返回部分结果、假设和缺口。结果与完整流程采用同一格式，可继续交给其他 agent 使用。

### 6.4 完成与异常

正常完成、带未知项完成、技术失败和显式暂停分别记录。API 中断采用有限重试；证据不足走知识缺口流程。自动运行以完成可支持的任务为目标，不以填满所有数值字段为目标。

默认生成节点报告并自动继续。观察模式保留为调试选项，只有显式开启等待时才暂停，不作为当前日常运行的人工关卡。

## 七、评估筛选与知识缺口

### 7.1 评分流程

保留新颖性、机理可行性、合成可行性、综合评分四类调用。LLM 给出带依据的维度分数，代码计算加权总分并检查裁决规则。

当前配置的起点为 5 次评分、评分 temperature 为 0。重复调用用于观察稳定性，不宣称统计独立，也不把重复一致当作正确性证明。调用次数是否减少，由后续同预算对照结果决定。

沿用当前阈值：总分 ≥ 7.0 且各维度 ≥ 5 为 pass；总分 < 5.0 为 reject；其余为 hold。关键证据不足、评分标准差超过 1.0 或聚合判断冲突时，优先保留 hold。

首版实施约定已更新为逐维度中位数聚合、各次总分的总体标准差检查，并由代码按阈值生成裁决，模型自报裁决仅留档；有效评分次数不足时保留 hold。具体默认值见 [实施计划](IMPLEMENTATION_PLAN.md)。这解决工程执行口径，不表示评分规则已经实现或完成校准。

### 7.2 三类缺失信息

| 情况 | 自动处理 |
|---|---|
| 能通过检索补齐 | 定向检索、提取、核验，更新依赖结果 |
| 可以在明确假设下判断 | 输出条件化结果，说明假设和影响 |
| 现有证据无法支持 | 保留未知，完成其他部分并记录缺口 |

检索获得的新信息不能冒充本案例缺失的实测 pH、溶解氧等参数。类似文献中的工况只能作为锚点条件或显式假设。

### 7.3 有限消解与重启

缺口处理经过检索、提取、自动检查、入库和重评。设置检索次数、嵌套深度、调用成本与重试上限，具体默认值待预算专题确定。

达到上限后标记为本轮未解决或预算耗尽，保留部分结果，继续其他候选。只有新的相关证据或新的运行请求才重新激活，不重复空检索。知识不足与有证据否定分别记录。

## 八、性能预测与机理探究

### 8.1 数值预测原则

优先寻找目标场景下的可比证据。记录材料、菌种、初始浓度、流动模式、时间含义、电极位置和其他关键条件的差异。

| 证据条件 | 输出 |
|---|---|
| 有较接近的材料和工况 | 文献锚定的预期范围，附外推依据 |
| 有相关证据但关键条件不同 | 条件化的粗略范围或趋势，明确外推程度 |
| 缺乏可比证据 | 暂不能定量预测，保留定性判断和缺口 |

尽可能给出便于比较的区间，但不为完成表格而生成无依据的上下界。文献数值的最小值与最大值不能自动作为新材料的预测区间。未经过校准的范围不称为统计置信区间。

### 8.2 量化结果

- 优先输出 H₂O₂、·OH 的浓度、生成量或速率。不同目标量分别记录，继承原始标定方式和单位。
- 对 ROS 贡献，先给出主要、次要或证据不足的判断；有充分支持时给出数值范围。
- 比较不同候选时对齐测量对象与工况，不把浓度、累计量、探针信号和 EPR 信号直接混排。
- 对当前案例输出关键运行时间点的出水 CFU 降低或 log 去除范围。真实灭活指标另列，不由出水计数自动推得。

检测限与删失数据保留原始含义。未检出不等于真实零值，不用零计数计算无限大的 log 去除。预测区间同时报告依据、宽度及无法比较的条件。

### 8.3 机理分析

机理记录区分阳极、阴极和溶液中的过程，说明 ROS 可能的生成、转化与作用位置。已知材料结构支持假设，但不自动证明运行中的活性相或主导路径。

输出支持证据、反向证据、主要替代解释和证伪条件。清除剂引起的效果变化不能未经论证就等同于某种 ROS 的精确贡献率。

方法边界的参考：CDI 氧还原研究表明两极电势分布会受副反应影响，见 [Shapira 等，2016](https://doi.org/10.1016/j.electacta.2016.10.127)。另一氧化体系的实验展示了清除剂对反应网络的干扰，见 [Alcohols as reactive species modulators](https://doi.org/10.1016/j.watres.2025.124849)。后者用于提醒核查方法适用性，不作为当前 CDI 案例的直接机理证据。

## 九、自动质量保障

1. **交叉提取**。不同模型分别提取，逐字段比对。冲突可交第三模型复核；仍无法支持的结果保持未知。模型一致不自动消除原文歧义。
2. **来源与结论检查**。同时检查证据 ID、原文位置、样品身份、条件和结论对应关系。
3. **数值与单位检查**。检查单位、数量级、上下界、时间定义和检测限。启发式异常只触发标记，不自动证明原文错误。
4. **反向证据检查**。保留相反结果，检查跨条件迁移与材料实体混淆。
5. **运行留档**。保存模型、提示词哈希、输入输出、证据快照、成本、时戳及错误。

近期不要求用户人工标注 10–20 篇文献。分别报告模型一致率、自动检查通过率、原文定位覆盖率、冲突率和未解决率。双方都缺失的字段单列，不能抬高已提取字段的一致率。

在没有独立核对集时，不把上述指标称为提取准确率。旧版“一致率 ≥ 90%”不再作为准确性验收依据。图表提取保持来源标记，未经验证不宣称读数准确。

## 十、回顾性验证与方法评估

### 10.1 结果留出的性能预测

预先声明可作为输入的材料组成、表征和工况。留出的 ROS 与抗菌结果只用于运行后的对比，不进入检索证据、归纳卡、示例提示词或微调数据。

固定输入、规则和模型后生成预测，再与已有实验数据比较。记录已知先导材料和已有数据的研究背景，将结果称为回顾性评估，不描述为先由系统发现、后开展的新实验。

### 10.2 已有结果下的机理解释

另设允许读取指定实验结果的解释任务。系统组织证据、分析机理和竞争解释。已提供的结果不能再作为独立命中指标；如有其他留出结果，单独用于核验。

两类任务分开运行和报告。预测任务中的失败可以成为分析对象，不能通过解释任务的结果覆盖原始预测记录。

### 10.3 单 agent 对照与模块移除对照

使用相同初始资料、可用工具和证据访问边界，设置相近总调用预算，比较单 agent 与完整多 agent 系统。记录模型组合、实际费用、耗时和重复次数。

分别评估交叉提取、知识缺口检索等模块的增益。移除某个模块时，其余条件保持可比。具体对照组合与运行次数在评估协议中确定，避免将更高调用成本误当成架构优势。

### 10.4 评价指标与结论范围

| 任务 | 报告内容 |
|---|---|
| ROS 量化 | 点估计适用时的偏差、区间覆盖、区间宽度、可输出数值的比例 |
| 出水菌数降低 | 对应运行时间点的 CFU 或 log 去除比较、检测限和缺失情况 |
| 真实灭活 | 仅在有匹配观测时评估；当前出水计数不能单独提供该标签 |
| 机理 | 得到支持、受到反驳和无法判断的结论，附证据范围 |
| 证据处理 | 定位、字段冲突、反向证据、自动检查与未解决项 |
| 排名与成本 | 排名对权重和重复运行的敏感性、费用、耗时、失败率 |

区间覆盖率与宽度共同报告，同时统计定量输出比例，避免以极宽区间或大量弃答获得表面好成绩。同一材料的多个时间点不当作多个独立材料验证案例。

五维总分衡量综合研究优先级，AUC ≥ 0.8 不再作为 P3 的硬性门槛。若以后获得可靠且工况可比的有效、弱效标签，可另设分类评估。未报告杀菌性能的材料和随机组合不能自动作为无效标签。

现有单一材料案例可以验证该案例下的预测与解释表现，不能单独证明跨家族排序正确或方法对所有材料有效。文献留出评估按论文和材料家族隔离，排除重复来源中的目标结果；预训练知识的潜在影响另行记录。

## 十一、模型与工具层

### 11.1 模型接入

延续角色名到模型配置的映射，计划采用 LiteLLM 适配。API key 从环境变量读取，agent 不绑定厂商。各角色的结构化输出与调用能力在部署时核查。

已有配置以 DeepSeek 为远程角色候选，本地推理候选为 Qwen3 系列。最新确认的部署环境是 Windows + WSL2、RTX 5090，首版同时使用远程和本地模型。原有 RTX 5090D v2、24 GB 记录以目标机器实测为准。首轮接通默认使用未微调 Qwen3-8B，共享一个本地服务；已有可用服务可以复用。Qwen3-30B-A3B 量化推理和 Qwen3-8B QLoRA 保留为后续选项，实际显存、上下文和吞吐需实测。

P1 的第二提取模型使用未微调本地模型，不能依赖 P5 才完成的微调模型。实施计划已经给出六类 agent、交叉提取和冲突复核的首版角色映射；已有配置文件仍待开发时迁移。若降级为单模型，明确记录降级状态。

本地推理保留 vLLM，微调保留 LLaMA-Factory 或 Unsloth 作为原方案选项。厂商、型号和软件兼容性不属于本版已经验证的实现结果。

### 11.2 工具优先级

优先建设工作区读写、材料实体规范化、文献检索、来源定位、单位规范化、证据关联、预算控制和运行记录。

文献工具保留 OpenAlex、Semantic Scholar、Crossref、Unpaywall，以及 GROBID 或 Marker 等解析选项。结构、吸附能、化合物和谱图数据库按任务接入；Materials Project、Catalysis-Hub、PubChem、CompTox、CoRE MOF、NIST XPS、NOMAD 等均为待核查覆盖范围的候选。DFT 接口放在后期。

所有外部工具统一封装、带时间戳缓存，并说明覆盖边界。数据库未返回结果表示未查得，不直接证明材料或性质不存在。

### 11.3 验证记录与可选约束

验证工具导入已有实验记录，关联预测版本，自动生成比较报告。验证结论按目标字段分别记录为支持、不支持或无法判断，并保留观测范围。

实验室设备约束保留为可选配置。本项目默认不启用。合成可行性仍按通用材料实验室条件评估。

## 十二、前端与运行报告

前端用于发起完整或独立任务、监控运行、浏览证据和修改配置。默认不承担逐步人工决策。MVP 先保证结构化结果与运行报告，完整界面在后续阶段完善。

保留 Streamlit 和五类页面的规划：

1. **运行总览**：任务入口、完整流程或子 agent 选择、状态、预算与日志。
2. **候选浏览器**：跨家族榜单、逐维分数、权重敏感性、性能范围、机理与未知项。
3. **工作区浏览器**：暂存区、正式区、来源定位、冲突与质量标记。
4. **配置页**：模型角色、权重、候选范围、场景、预算和观察模式。每次修改产生版本。
5. **缺口与验证**：缺口处理历史、实验对比、单 agent 与多 agent 方法评估。

## 十三、MVP 与开发路线

### 13.1 MVP 定义

以一批来源可追溯的可用文献、当前场景和有限跨家族候选为输入。系统自主完成候选生成、评估、性能预测和机理探究，形成候选档案、可调整榜单和运行报告。

六类子 agent 均有独立调用入口。关键缺口触发自动补充处理，并在预算内结束。结果区分可量化、条件化判断和未知项。

在导入已有案例数据后，完成结果留出的预测对比、已有证据下的机理解释，以及单 agent 对照。至少展示有依据的定量输出；如果证据仍不足，应报告定量目标尚未达成，不能用任意区间充数。

### 13.2 阶段划分

下表保留设计层的 P0–P5 路线。实际代码实施按 [实施计划](IMPLEMENTATION_PLAN.md) 的 M0–M6 执行；首版包含五类基础页面，完整 UI 的打磨、微调与扩展数据库仍可后置。

| 阶段 | 工作内容 | 验收重点 |
|---|---|---|
| P0 | 数据契约、证据规则、场景与留出边界；相关性和全文可用性审计 | 字段含义明确，权限路径和未知项处理明确；不要求用户补齐实验参数 |
| P1 | 工作区、文献提取与自动检查 | 能定位原文，保留冲突、缺失与权限；报告一致性及自动检查指标 |
| P2 | 知识归纳、材料实体与候选空间 | 基元库可支撑跨家族生成；指定材料来源可追溯 |
| P3 | 候选生成与筛选、独立调用、排名版本 | 评分有依据，算术可复算，调整可追溯，缺口处理有界 |
| P4 | 性能预测、机理探究、案例对比与方法对照 | 完成完整流程和独立任务，报告定量表现与局限；MVP 达成 |
| P5 | 完整前端、可选本地微调、扩展数据库和验证工具体验 | 改善成本、吞吐和使用体验，不要求重做一套材料实验 |

各项数值验收阈值在数据审计和评估协议完成后确定。旧版 P1 一致率与 P3 AUC 门槛不直接沿用为科学有效性标准。

## 十四、风险与待定事项

| 风险 | 处理方式 |
|---|---|
| 可比的定量证据少 | 审计后确定范围，允许趋势和未知项，报告定量输出比例 |
| 排名随研究偏好变化 | 保留分数和证据，版本化权重，正式评估前固定规则 |
| 已有实验结果泄漏 | 声明输入和留出范围，隔离证据快照，分开预测与解释任务 |
| 模型共同误读 | 原文定位、字段检查和冲突留存，不将一致率当准确率 |
| 阴阳极或材料形态混淆 | 记录电极位置、原始框架、衍生相和证据条件 |
| 未知工况影响数值 | 检索背景证据、明确假设、扩大有依据的范围或弃答 |
| 缺口导致无限循环 | 检索、调用成本、嵌套与重试上限；相关新证据才触发重启 |
| 单一样品无法验证全榜单 | 限定结论范围，方法对照与文献留出评估分别报告 |

以下专题按用户最新指示暂缓深入讨论；首版所需的简单默认值已写入实施计划：

1. 六类 agent 的输入输出契约、字段归属和工作区权限。
2. 证据、预测、知识缺口和验证记录的详细字段及状态规则。
3. 结果留出、单 agent 对照、模块移除对照与预算口径。
4. 候选组合生成、材料同义词、评分聚合与冲突处理的具体规则。
5. 全文访问审计、初期模型角色和工具配置。受限来源单独处理。
6. 存储与检索的进一步扩展；首版默认使用 SQLite 与全文检索。

人工文献标注和新增实验均不列为近期前置任务。本轮交付可转交 coding agent 的实施文档，不编写项目代码；后续接到实施任务的 agent 按 M0–M6 推进，不将上述专题作为开工前置条件。
